# CLAUDE.md

This repo is the Wahoo Bay fish-identification system: the worker (detector + classifier on the camera stream), the FastAPI dashboard, the SenseStream poller and Postgres. The same code runs in three shapes: the DGX (bare metal, `scripts/dev/*.sh`), a laptop (`make up`: compose profiles `web` / `gpu` / `cpu`, `make seed` for the sample dataset) and AWS (App Runner + Lambdas, defined in the sibling repository `wahoobay/infra`, whose design spec §4.5 describes where this system is going and whose README is the runbook).

## Ground rules

- **Production runs from the DGX checkout** at `/raid/scratch/dzimmerman2021/wahoobay`, 24/7, serving the public demo. Never stop, rebuild or migrate the database there casually; production owns the ports, so a second checkout there is for `pytest` and `ruff`, not for a compose stack. See `docs/operations.md`.
- **No AWS credentials in this repo or on the DGX.** Code reaches AWS only through GitHub Actions and the OIDC roles defined in `infra` (CI pushes images to ECR from `main`). Secrets live in `.env` (ignored) locally and in Secrets Manager / GitHub secrets for pipelines; never in code, commits, logs or chat.
- **Location is configuration.** The site (`LOCATION_ID`, `SENSESTREAM_DEPLOYMENT_URI`, `TZ`), the database (`DATABASE_URL` or `DB_*`), storage (`FRAMES_URL`, `MODELS_URL`) and features (`FEATURE_REVIEW_TOOL`, `LIVE_VIDEO_EMBED_URL`, …) come from the environment; `tests/test_config.py` keeps `wahoo_<n>` and `/raid/scratch` out of `services/` and `scripts/` (the DGX launchers in `scripts/dev` export the Wahoo Bay values). The README's "Environment contract" lists them.
- **The dashboard holds no state between requests**: periodic work is a job (`app.jobs`), the schema is Alembic (`db/migrations/versions/`; `python -m app.migrate`), frames and weights live behind URLs (`services/common/storage.py`).
- **Tests first.** `ruff check .`, `ruff format --check .` and `pytest` are what CI runs; set `TEST_DATABASE_URL` to a scratch PostgreSQL (never the production `wahoobay` database) for the database tests, which otherwise skip. `docker compose config` if compose changed. Model weights, frames, logs and exports never enter git (see `.gitignore`); the committed `data/sample` is synthetic.
- Docs: `docs/architecture.md`, `docs/operations.md`, `docs/data_pipeline.md`, `docs/finetune_workflow.md`, `docs/reviewer_guide.md`. `PLAN.md` is the original DGX plan.
