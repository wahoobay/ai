# CLAUDE.md

This repo is the Wahoo Bay fish-identification system: the worker (detector + classifier on the camera stream), the FastAPI dashboard, the SenseStream poller and Postgres. The same code runs in two shapes: a laptop (`make up`: compose profiles `web` / `gpu` / `cpu`, `make seed` for the sample dataset) and AWS (App Runner, Lambdas and a GPU host, defined in the sibling repository `wahoobay/infra`, whose design spec §4.5 describes where this system is going and whose README is the runbook). It also used to run on FAU's DGX (bare metal, `scripts/dev/*.sh`); nothing runs there any more.

## Ground rules

- **Nothing runs on the DGX any more.** Dan shut it down on 2026-11-15 when the system moved to AWS: don't restart it, deploy to it or report it as down. `scripts/dev/*.sh` and `docs/dgx-history.md` describe that old install; `docs/operations.md` is the runbook for AWS.
- **The live system is the AWS stack `ai-wahoobay-staging`** in us-east-1 (`staging-ai.wahoobay.net`: the App Runner dashboard, Aurora, the jobs Lambda and the GPU host `ai-wahoobay-staging-gpu`, which runs the worker). Every push to `main`, even a docs-only one, rebuilds the image and redeploys it, restarting the worker, so merges to `main` are timed with Dan. `ai-wahoobay-prod` is defined in `infra` but not deployed; production deploys are `deploy-prod.yml`, run by hand.
- **No AWS credentials in this repo or on the DGX.** Code reaches AWS only through GitHub Actions and the OIDC roles defined in `infra` (CI pushes images to ECR from `main`). Secrets live in `.env` (ignored) locally and in Secrets Manager / GitHub secrets for pipelines; never in code, commits, logs or chat.
- **Location is configuration.** The site (`LOCATION_ID`, `SENSESTREAM_DEPLOYMENT_URI`, `TZ`), the database (`DATABASE_URL` or `DB_*`), storage (`FRAMES_URL`, `MODELS_URL`, `NEGATIVE_REGIONS_URL`) and features (`FEATURE_REVIEW_TOOL`, `LIVE_VIDEO_EMBED_URL`, …) come from the environment; `tests/test_config.py` keeps `wahoo_<n>` and `/raid/scratch` out of `services/` and `scripts/` (the DGX launchers in `scripts/dev` export the Wahoo Bay values). The README's "Environment contract" lists them.
- **The dashboard holds no state between requests**: periodic work is a job (`app.jobs`), the schema is Alembic (`db/migrations/versions/`; `python -m app.migrate`), frames and weights live behind URLs (`services/common/storage.py`).
- **Tests first.** `ruff check .`, `ruff format --check .` and `pytest` are what CI runs; set `TEST_DATABASE_URL` to a scratch PostgreSQL (never a deployed database such as staging's Aurora) for the database tests, which otherwise skip. `docker compose config` if compose changed. Model weights, frames, logs and exports never enter git (see `.gitignore`); the committed `data/sample` is synthetic.
- Docs: `docs/architecture.md`, `docs/operations.md`, `docs/data_pipeline.md`, `docs/finetune_workflow.md`, `docs/reviewer_guide.md`. `PLAN.md` is the original DGX plan.
